## Choices made before building

| Choice | Decision | Why |
|---|---|---|
| Live editors | Real ProseMirror `EditorView`s (and Tiptap `Editor`s for gate D) in **jsdom**, one Node process per gate run, each editor with its own `Y.Doc` and its own WebSocket connection to a real relay on 127.0.0.1. | Spikes 1 and 2 already run ProseMirror under jsdom; the thing under test is the binding and the relay, not browser input handling. Deterministic, fast, no 150 MB browser download. Limitation stated in findings: no real DOM input events, IME or selection rendering; typing, paste, split and join are driven through `EditorView` APIs (`dispatch`, `pasteHTML`, `pasteText`, prosemirror-commands). |
| Relay process | The relay runs as a **child process** started by the gate harness, bound to 127.0.0.1, killed at the end of every run (including on failure). | Gate G needs a real restart; a child process makes "stop every server" checkable. |
| Ports | Stack 13 uses 4210 to 4239, stack 14 uses 4240 to 4269, the orchestrator's ad hoc runs 4270 to 4299. | No collisions between the two stacks' runs. |
| Stack 13 workarounds | Root attributes (`lead`, `eol`) live in a sibling `Y.Map`, kept in sync with `doc.attrs` by a small ProseMirror plugin. Atom marks: spike 1's schema already has a meta attr `leafMarks` on every inline leaf; a ProseMirror plugin keeps `leafMarks` equal to the leaf's marks on local edits and restores marks from `leafMarks` on remote ones, so the binding stays stock. A binding patch is sized on paper for comparison. | Keeps y-prosemirror / y-tiptap unpatched, so upgrades stay free; spike 1 designed the attr for exactly this. If the plugin approach cannot be made loss-free, fall back to a `patch-package` patch of `@tiptap/y-tiptap`. |
| Stack 13 binding | `@tiptap/y-tiptap` 3.0.9 for both raw ProseMirror editors and Tiptap, so one binding is under test. | Tiptap 3's collaboration extensions sit on y-tiptap, not y-prosemirror. |
| Stack 14 relay | Try in order: Hocuspocus 4.7 with `yjs` and `y-protocols` aliased to `@y/y` and `@y/protocols` by npm `overrides`; stock Hocuspocus 4.7 with Yjs 13 as a relay for Yjs 14 clients (expected to fail if the update formats differ); a minimal custom relay on `@y/protocols` and `ws`. Record every attempt. | Hocuspocus uses only `Doc`, `applyUpdate`, `encodeStateAsUpdate`, `mergeUpdates`, `snapshot`, `snapshotContainsUpdate` from yjs (checked in its dist), so aliasing is plausible. |
| Schema | Spike 1's schema, parser, serializer and codec, copied from `1e1f4a6`, in both stacks. Gate F uses spike 2's own schema and scenario, copied from `88bd85c`, because the rebase code is written against it. | Charter reuse list. |

## Common gate harness (both stacks, same shape)

- `npm run gates` runs every gate, prints one Markdown table (gate, result, numbers) and writes `results/gates.md` and `results/gates.json`. Exit code non-zero on any failure. `npm run gates:quick` runs a small subset for builders.
- Fixture `fixtures/live.md`: front matter, a leading blank line so `lead` is non-default, a linked badge `[![ci](badge.svg)](https://ci.example)`, a link containing text and an image, inline HTML, a footnote reference and definition, a hard break, a table, nested lists, a fenced code block, an HTML block. Same file in both stacks.
- Equality check used everywhere: ProseMirror JSON of the whole doc including `doc.attrs` and marks on every inline leaf; plus `serializeDoc` of both sides succeeds and is byte-identical.
- Gate B script (identical in both stacks): editor 1 types a word character by character inside a paragraph; pastes HTML containing bold text and a linked image; splits the paragraph that holds the linked badge right before the badge and joins it back; adds a link mark to an unlinked image; deletes a range spanning two blocks. Editor 2 concurrently types into a different paragraph. After settling, editor 1, editor 2 and the relay's stored document are equal as defined above. Stack 13 also runs the script **without** workarounds as a negative control that must show the loss.
- Gate C (stack 13; stack 14 measures the same thing with no workaround): at least 50 real corpus files (use all fetched real files if fast enough): parse, load into editor 1 through the live sync plugin, read in editor 2 and on the relay, serialize, byte-identical to the original file. Compare with spike 1's A3 result (160/294 on plain y-prosemirror).
