## 1. The one idea

A file save is an external edit with an unknown base. The daemon keeps a short history of the file versions it knows the editor could have loaded, each with a Yjs snapshot of the document at that version. On a save, it picks the most plausible base, forks the CRDT at that base's snapshot, applies a two-way diff from the base's content to the saved content on the fork, and merges the fork back into the live document. This is spike 2's rebase mechanism (fork at base, two-way diff, CRDT merge) applied to file saves. A fresh save is the special case where the base is the current state, and then the diff is applied to the live document directly.

Consequences:

- Stale saves (gate D) cannot revert remote edits, because the diff only contains what differs between the base and the save. Remote edits made after the base are concurrent with the fork and survive the merge.
- Concurrency (gate E) is ordinary CRDT merge.
- Restart (gate H) is the same operation with the persisted base.
- A fast-forward `git pull` that changes the file (gate G) is the same operation with a git author instead of the local user.

## 2. Components

```
remote client (headless, stands in for the browser)
      │ y-protocols over WebSocket
relay: Hocuspocus 4, 127.0.0.1:41xx, in memory, Y.Doc gc: false
      │
daemon: HocuspocusProvider, Y.Doc gc: false
  ├── DocSync (core, pure, no I/O): versions, base choice, import, render
  ├── FileSide: watcher, settle debounce, guarded atomic write, echo check
  ├── GitWatch: HEAD, branch, refs/stash, index.lock; attach / detach / rebase
  └── Persist: state under <repo>/.git/phraise/daemon/<doc>/
```

## 3. Core: DocSync (pure, synchronous, no I/O)

### 3.1 Document representation

The copied spike 1 model (`src/md/`): `parseMarkdown`, `serializeDoc`, `docToYDoc`, `yDocToDoc`, `encodeLeafMarks`. Y layout: `XmlFragment('prosemirror')` holding the y-prosemirror encoding of the doc with inline leaf marks encoded in `leafMarks`; `Map('phraise-doc')` holding root attrs `lead` and `eol`; `Map('phraise-authors')` mapping a client ID (string) to `{ name, kind: 'local' | 'remote' | 'git', at }`. Every `Y.Doc` in this spike uses `gc: false`, because forks need tombstones (`Y.createDocFromSnapshot` refuses a garbage-collected doc).

### 3.2 Versions and base choice

A version is `{ seq, text, hash, snapshot, origin: 'write' | 'import' | 'adopt' | 'restore', at }` with the invariant: forking the live doc at `snapshot` and rendering gives `text`. For a daemon write, `snapshot` is taken at render time. For an import, `snapshot` is the fork's snapshot after the diff, not the live doc after the merge, because the fork is exactly what the editor saved.

The ring keeps the last 32 versions. The **anchor** is the newest version whose origin is `import`, `adopt` or `restore`: the file side certainly had it. Candidates are the anchor and every version after it. If no anchor is in the ring, all retained versions are candidates.

`chooseBase(text)`: cost(v) = characters in removed plus added lines of a line diff between `v.text` and `text`, after trimming the common prefix and suffix. Minimum cost wins; ties go to the newest. Cost 0 means the save equals a known version: nothing to import.

Why these rules:
- Minimum cost picks the base that explains the save with the fewest user edits. If the user made the same edit as a remote peer, the newest version wins with cost 0 and nothing is applied, which is right.
- Restricting to the anchor and later versions handles undo: after the user saves V1 and then undoes to V0's bytes, V0 is older than the anchor and cannot be chosen, so the undo is imported as an edit.
- Known ambiguity, accepted and documented: the user reloads a daemon write that contains a remote insertion and deletes exactly that insertion. The save equals an older candidate, so it looks like a stale unchanged save and the deletion is not applied. The failure deletes nothing.
- Known limit: two editors with different stale buffers of one file. The older one's base may be outside the candidates.

### 3.3 Import

```
importText(text, { author, base? }):
  base = base ?? chooseBase(text).base
  if cost 0: record nothing new; return { kind: 'noop' }
  newDoc = parseMarkdown(text).doc
  target = equalSnapshots(snapshot(live), base.snapshot) ? live            (fast path, live clientID)
                                                         : fork(live, base.snapshot, fresh clientID)
  target.transact(() => { register author for target.clientID; set lead/eol; applyDiff(fragment, current(target), encodeLeafMarks(newDoc)) }, ORIGIN_IMPORT)
  verify: JSON of yDocToDoc(target) equals JSON of newDoc, meta attrs included. On mismatch: repair with
          y-prosemirror updateYFragment on the whole fragment and count it as a `repair`.
  if forked: apply encodeStateAsUpdate(fork, svBeforeDiff) to live with ORIGIN_IMPORT
  record version { origin: 'import', text, snapshot: snapshot(target) }
```

### 3.4 The two-way diff `applyDiff(yParent, aChildren, bChildren)`

Adapted from spike 2's `src/diff.ts` (copy it, note origin), extended for spike 1's schema.

1. **Align** children by LCS on a semantic key: `JSON.stringify(stripMeta(child).toJSON())`.
2. **Matched pairs** (semantically equal): if the Y element's attributes differ from B's (typically `src` or `gap` after a whitespace-only or syntax-only change such as `*a*` to `_a_`), set B's attributes on the element and, recursively, on nested elements of the same shape. Never touch text.
3. **Unmatched runs**: pair nodes of the same type whose word Dice similarity is at least 0.5 (spike 2's rule), in order; the rest are deletes and inserts.
4. **Paired, not equal**: set B's attributes. If the node is a textblock (`paragraph`, `heading`, `table_cell`, `code_block`, `raw_block`), run the textblock diff. Otherwise recurse into children.
5. **Textblock diff.** y-prosemirror stores a textblock's content as Y children: one `Y.XmlText` per run of text (marks as formatting attributes keyed by mark name) and one `Y.XmlElement` per inline leaf (`image`, `hard_break`, `raw_inline`). Split both sides into text groups separated by inline leaves. If the leaf sequences have the same length and types, and the Y side has no two adjacent `XmlText` children: sync each leaf's attributes, and for each text group run a word-level diff (`diffWordsWithSpace`) on the plain text, then a formatting pass so the marks equal B's (spike 2's `reformatToMatch`). Otherwise fall back to `updateYFragment` for this one textblock and count a `coarse-textblock`.
6. **Inserts** build new Y subtrees from B, as spike 2's `buildYNode`, extended for inline leaves.

Why word level and not y-prosemirror's own `updateYFragment` everywhere: `updateYFragment` replaces one contiguous range per textblock and pairs block children greedily from the left. On a stale save, a replaced range re-inserts text a remote peer deleted meanwhile (a reverted remote edit), and an inserted paragraph shifts every following sibling's content into its neighbour. Spike 2 measured it worse on anchors (71 against 76.6 percent).

### 3.5 Render

`render()`: `serializeDoc(yDocToDoc(live))`. Throws `UnverifiedSerializationError`, which the daemon reports and then skips the write. Whole-document check in debug and gate mode: `parseMarkdown(out)` must be semantically equal to the doc, because block serialization is verified per block in isolation and some constructs are not compositional (an unclosed fence that is no longer last swallows what follows). Count violations; fixing them is a finding, not a precondition.

## 4. Daemon runtime

### 4.1 One serial queue per document

Every step that reads or writes the file or the version ring runs in one async queue per document. Remote Yjs updates can apply between steps; that is safe because imports fork at a recorded snapshot.

### 4.2 Remote change to file (gate A)

On any Y update whose origin is not the daemon's own import: schedule an export with a trailing debounce `REMOTE_DEBOUNCE_MS` (start at 30) and a max wait `REMOTE_MAX_WAIT_MS` (start at 200). Export, all with synchronous fs calls so no JS runs in between:

```
fd = open(path, 'r'); st = fstat(fd); disk = read(fd)
if disk != lastKnown: close; enqueue import; return            (a save we have not seen yet: import first)
text = render(); snap = snapshot(live)
if text == disk: record version('write', text, snap) if new; return
write tmp beside the file (same dir, hidden name, same mode); st2 = stat(path)
if st2 differs from st in ino, size or mtimeMs: unlink tmp; enqueue import; return
rename(tmp, path)
st3 = fstat(fd)   (old inode)  if size or mtimeMs changed since st: an in-place writer hit the window;
                  read its bytes from fd and enqueue them as a save
close(fd); lastKnown = text; record version('write', text, snap); persist
```

If the path is a symlink, write to its target. Leftover tmp files are removed at start.

### 4.3 File to remote (gates B, C)

`fs.watch` on the file's directory, filtered by name (survives rename-over saves), plus a 2 s poll as a safety net. Each event (re)starts a settle timer `FILE_SETTLE_MS` (start at 30). When it fires: if `.git/index.lock` exists, re-arm and wait. Read the file. If the bytes equal `lastKnown`: nothing (this is the echo check; it is content based, never time based). If the file is empty and `lastKnown` was not, wait `EMPTY_GRACE_MS` (250) and re-read, because truncate-then-write editors pass through an empty file. Then the git check (4.5), then `importText(text, { author: local user })`, `lastKnown = text`, persist, then schedule an export (it will usually find render equal to disk and write nothing, which is gate F).

### 4.4 Persistence and restart (gate H)

State directory `<repo>/.git/phraise/daemon/<docName>/`, inside `.git` so it is never in the working tree: `base.md` (the last version known to equal disk), `base.snapshot` (its encoded snapshot), `ydoc.bin` (full state update of the live doc), `state.json` (doc name, relay URL, user, branch, HEAD, attached or detached, reason). Written with tmp plus rename after every import and export.

Start: remove tmp leftovers; load `ydoc.bin` into the Y.Doc if present; connect and sync; read disk. If no state: adopt (relay doc empty: seed it from the file; relay doc not empty and disk equals render: record; otherwise conflict). If disk equals `base.md`: export. Otherwise import with base = the persisted version. If the snapshot cannot be forked (state deleted, relay doc replaced): if disk equals render, record; else write `<name>.phraise-conflict-<yyyymmdd-hhmmss>.md` beside the file containing the CRDT's render, leave the file untouched, mark the document detached, and log why.

### 4.5 Git underneath (gate G)

Git state = `{ branch (symbolic-ref or null when detached), head (rev-parse HEAD), stash (rev-parse -q refs/stash or null) }`, read with `git` subprocesses, compared with the recorded state at every import and export, and on changes to `.git/HEAD`, `.git/refs/**`, `.git/packed-refs` (watch `.git` non-recursively plus the branch's ref directory, or poll every 500 ms; builder's choice).

| Observation | Action |
|---|---|
| HEAD moved, same branch, file unchanged (commit, amend, reset --soft) | Record new git state. Log "commit observed". Harmless. |
| Branch changed or HEAD detached, file changed or not | Detach: stop importing and exporting this document, keep the CRDT, log the reason. |
| Same branch, new HEAD is a descendant of the old one, file changed | Re-base: import the change with base = last known version, author = git author of the new HEAD (kind `git`). Log it. |
| Same branch, HEAD moved not as a descendant, file changed (reset --hard, rebase) | Detach. |
| Stash ref changed and file changed | Detach. |
| Refs unchanged, file changed, `index.lock` was seen during settle | Detach (`git checkout -- f`, `git restore`). |
| Detached, and branch equals the attached branch and disk equals `lastKnown` | Reattach, then export (covers `stash` then `stash pop`, and switching back). |

The daemon never writes the file while detached, and every attach, detach and re-base emits an event with a reason.

### 4.6 Events

The daemon emits structured events (an EventEmitter in process, JSON lines on stdout in the CLI): `import {hash, base, forked, changedBlocks, coarse, repair, ms}`, `import-noop {hash}`, `export {hash, ms}`, `export-skip {reason}`, `detach {reason}`, `attach`, `rebase {head, author}`, `conflict {path}`, `error {message}`. Tests and gates assert on them.

## 5. Test harness

- Relay in process on a port in 4100 to 4199 (tests pick a free one in that range), `yDocOptions: { gc: false }`, no persistence.
- Remote client: a `Y.Doc` with a `HocuspocusProvider` and a `RemoteEditor` that edits like a browser: read the doc with `yDocToDoc`, apply a ProseMirror transaction, write back with `updateYFragment` after `encodeLeafMarks`, as `ySyncPlugin` does.
- Each test makes its own `git init` repository under `$TMPDIR` and removes it. Never the Phraise repository.
- Editor save styles: in place (`writeFile` on an open fd without truncating first where possible), rename-over (write `.tmp` then rename), truncate then write (truncate, a short pause, then write).

## 6. Gates, how each is measured

| Gate | Measurement |
|---|---|
| A | 200 remote word edits on a corpus README, each timed from the remote transaction to the file containing it. Median and p95. After each, every block the edit did not touch is byte-identical. |
| B | 100 file edits per save style, timed from the write to the remote client seeing the change. Decode each import's update: every inserted item and deleted item lies inside the edited top-level block; every inserted item's client maps to the local user. |
| C | Echo counter: an import whose bytes were not written by the test is an echo. 200 rapid alternating rounds (remote edit, file save, with 0 to 20 ms gaps). Zero echoes, and zero imports of daemon-written bytes. |
| D | Scripted stale saves: editor loads V0, remote edits produce V1 and V2, editor saves V0 plus its own edit. Remote edits all present afterwards, the editor's edit present, final file equals render. Also in-memory in the core tests. |
| E | Concurrent edits in different blocks and in the same block, many timings. Replicas converge (equal state vectors and equal render), every inserted token present, file equals render. |
| F | Core only, no relay: corpus files with random editor-like byte edits, and at least 30 hand-made half-typed states inserted at several positions. Import, then render must equal the saved bytes. Report the rate and every failure. |
| G | Scripted git operations in a temp repo: commit, branch switch changing the file, branch switch not changing it, fast-forward pull, stash and stash pop, reset --hard, checkout -- file. Check the action table above, no import attributed to the local user, file never written while detached. |
| H | Stop the daemon, edit both sides, restart: merged. Delete the state and repeat: conflict copy written, file untouched. Also a SIGKILL variant through the CLI. |
| I | 300 seeded trials interleaving saves (all three styles), remote edits, stale saves, restarts and delays. Per trial: no exception, convergence, no lost token except the accepted delete-versus-edit category, no echo. Failures categorized. |
| J | The 240 KB spike 1 file: import and export time with and without a verification cache (memoize block verification by `src`, node JSON and definitions context). |
