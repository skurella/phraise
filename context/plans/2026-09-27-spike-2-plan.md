This file is the algorithm specification every spike-2 brief points to. Builders implement it; they do not redesign it. Deviations go in the builder's log with a reason.

## 1. Core idea: rebase = fork at base, two-way diff, merge

The live CRDT document was seeded from commit A. Every item that existed at A is identified by a CRDT **snapshot** `S_A` (Yjs: state vector plus delete set, `gc: false`; Loro: frontiers).

To rebase onto commit B:

1. **Fork** the live document at `S_A`. Yjs: `Y.createDocFromSnapshot(live, S_A, new Y.Doc({gc:false}))`, which keeps item IDs. Loro: `doc.forkAt(frontiersA)`. The fork's content equals commit A exactly, whatever the live doc contains.
2. Give the fork a **deterministic peer ID**: `hash32(docId + ":" + baseId + ":" + targetCommit)`, never 0. Register it in the author registry as a git peer.
3. Apply a **two-way diff** pmA to pmB on the fork (section 3). Afterwards the fork's content must equal pmB exactly at the ProseMirror-JSON level. This is asserted on every rebase.
4. Write the **rebase record** and advance the **base pointer** on the fork (section 4).
5. Export the fork's changes since the fork point as one update and **apply it to the live doc**. The CRDT merge does the three-way work: every live edit made since A is concurrent with the rebase branch.

Consequences, verified by a prototype on 2026-09-27 (see log):

- Because the fork point, the diff and the peer ID are all deterministic, two replicas running the same rebase produce byte-identical updates, and Yjs dedupes them. The rebase is idempotent and may run on any replica that has `S_A`, including a replica that holds extra unsynced edits.
- No three-way alignment code is needed. Server-side synced-but-uncommitted edits and offline edits are handled by the same path.
- The next base `S_B` is the fork's snapshot after step 3 plus the base pointer write, so every base is a pure commit state inside CRDT history. Chained rebases A to B to C work the same way.

## 2. Document model

- Own ProseMirror schema: `doc`, `paragraph`, `heading(level)`, `bullet_list`, `ordered_list(order)`, `list_item`, `blockquote`, `code_block(params)`, `horizontal_rule`, `text`; marks `em`, `strong`, `code`, `link(href, title)`. No inline nodes other than text, so every textblock maps to exactly one `Y.XmlText` in y-prosemirror's encoding (verify this).
- Markdown to PM: `prosemirror-markdown`'s `MarkdownParser` with markdown-it `commonmark` preset, images and raw HTML rendered as plain text or ignored, hard breaks ignored. Tables etc. fall back to paragraphs, which is fine. Byte-exact Markdown is out of scope; compare at PM-JSON level.
- Seeding: `prosemirrorToYXmlFragment` into fragment `"pm"` with a deterministic seed peer ID `hash32(docId + ":seed:" + commit)`, gc off. So two replicas seeding the same commit produce identical docs.
- **Doc plain text** for comment selectors: textblock texts in document order joined with `"\n"`. Provide a mapping between global offsets and `(XmlText, index)`.
- Root types in the Y doc: `pm` (XmlFragment), `phraise` (Map: base pointer, rebase records, snapshots), `authors` (Map), `comments` (Map), `review` (Map).

## 3. Two-way diff pmA to pmB (applied to the fork)

Recursive over the tree, `diffChildren(yParent, aChildren, bChildren)`:

1. Align children with an LCS on a structural hash (type + attrs + full content). Equal pairs are skipped.
2. Inside each run of unmatched A and B children, pair A and B children in order when they have the same node type and similarity >= 0.5 (word-level Dice or similar). Unpaired A children are deleted, unpaired B children inserted at the right index.
3. For a paired node: set changed attrs; if container, recurse; if textblock, apply a **text diff** at the configured granularity.

Granularity (configurable, default `word`):

- `word`: jsdiff `diffWordsWithSpace` on plain text, then a format pass so marks equal pmB's (y-prosemirror encodes a mark as an XmlText attribute `markName -> mark.attrs`; match its exact encoding).
- `char`: jsdiff `diffChars`, same format pass.
- `block`: replace the textblock's whole text.
- `yprosemirror`: call y-prosemirror's own `updateYFragment` on the fork's fragment with pmB (prefix/suffix diff). Used only as a comparison point.

All ops must be deterministic for identical input.

## 4. Records in the `phraise` map

- `base`: `{ id, commit }` pointing at the current base. Written in the same transaction as the diff so it is inside `S_B`, and so a later rebase's write causally supersedes it.
- `rebase:<id>`: `{ id, baseId, baseCommit, targetCommit, author: {name,email}, peer, granularity }`.
- `snapshot:<id>`: base64 of `Y.encodeSnapshot` for the base with that id (seed or rebase). Written in a second transaction by the same deterministic peer, after the snapshot is taken. Unique key, never conflicts.
- `authors` map: `clientID -> { kind: "human", userId, name } | { kind: "git", name, email, commit }`. Humans register on connect, as a Hocuspocus `onAuthenticate` hook would. Git peers are registered inside the deterministic transaction.

## 5. Integration on every replica: needs-review and resurrection

A replica's sync layer takes `P = Y.snapshot(doc)` before applying each remote update batch. After applying, for every rebase record it has not processed before (tracked locally, and recorded in the `phraise` map as `ack:<rebaseId>:<clientID>`):

- `S_A` = snapshot of the record's base, `S_B` = snapshot of its result.
- `upstreamChanged` = textblock elements whose content at `S_B` differs from `S_A`, including elements deleted in `S_B` and elements new in `S_B`.
- `localChanged` = textblock elements whose content at `P` differs from `S_A`, including local deletions. Content at a snapshot is rendered with `XmlText.toDelta(snapshot)` and `Y.isVisible`.
- **Needs review** = `upstreamChanged ∩ localChanged`. Write `review[elementIdString] = { rebaseId, reason: "concurrent-edit" }`.
- **Resurrection**: for each textblock element deleted by the rebase that contains visible-at-`P` items inserted by this replica's own client ID with clock at or after `S_A`'s state vector for that client, re-insert the block as rendered at `P` at the nearest valid position under its nearest live ancestor (wrap in `list_item` if the ancestor is a list), and flag it `reason: "deleted-upstream-edited-locally"`. Only the author of the items resurrects, so it happens once per author.
- All of this runs in one local transaction. Flags are idempotent map writes, so the final flag set does not depend on delivery order.

The rebase runner itself goes through the same integration path when it applies the fork update to its live doc.

## 6. Comments

Anchor record in `comments` map: `{ id, author, body, start: RelativePosition JSON (assoc 0), end: RelativePosition JSON (assoc -1), quote: { exact, prefix(32), suffix(32) }, pos: { start, end } }`.

Resolution, a pure function of the doc:

1. **CRDT**: resolve both relative positions. If both resolve and start < end, the result is `{ method: "crdt", range }`.
2. **Fuzzy**: otherwise search the doc plain text for `exact` with `approx-string-match`, max errors = `min(64, ceil(0.25 * exact.length))`. Score candidates Hypothesis-style: quote similarity weight 50, prefix 20, suffix 20, position proximity 2. Accept the best candidate only if quote similarity is at least 0.75; the result is `{ method: "fuzzy", range, score }`.
3. Else `{ method: "orphaned", quote }`. The stored record keeps its quote forever.

Re-seed (decision D1): `reseed(oldDoc, markdown, commit)` builds a fresh doc, resolves each comment in the old doc, refreshes its selectors from the old doc's text, anchors it in the new doc by selectors only, and writes fresh relative positions.

## 7. Attribution

`listAttribution(doc)`: for every textblock, runs of visible characters grouped by inserting client ID, mapped through `authors`. Output `[{ blockPath, from, to, text, author }]`.

## 8. Gates and harness

A replica harness with named replicas, an explicit update queue per link, connect/disconnect, and delivery in any order. `npm run gates` prints a table of gates A to H with pass/fail and numbers, and exits non-zero on failure. Unit tests with vitest via `npm test`.
