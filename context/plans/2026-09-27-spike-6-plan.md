## 2. Module layout

One npm package: `spikes/2026-09-27-integration-engine/`. TypeScript, ESM, `tsx`, `vitest`. Pinned versions from spike 5: `yjs` 13.6.33, `@tiptap/y-tiptap` 3.0.9, `@hocuspocus/server`, `/provider`, `/extension-sqlite` 4.7.0.

```
src/
  markdown/   parse, serialize, schema, style, compare. No Yjs. Pure functions.
  crdt/       THE ONLY MODULE THAT IMPORTS yjs, y-protocols or @tiptap/y-tiptap.
              The five-point interface (section 3).
  engine/     Rebase, file/text import, comments store, review flags, attribution listing,
              commit preparation (serialize + trailers), generations. Uses crdt + markdown.
  git/        Git storage against a remote given by URL/path: head polling, read file at commit,
              draft flush and restore (lease), commit (lease). Shells out to the git CLI. No Yjs.
  relay/      Hocuspocus server as a library (startRelay) plus cli.ts. Auth stub, forged-ID
              rejection, open-and-seed, draft flusher, head poller, commit, compaction. HTTP control API.
  daemon/     Spike 3's daemon on top of engine + crdt, plus the local save interface (gate J).
  testkit/    Temp bare remote and clones, live jsdom editor client, relay harness (in-process and
              child-process), port allocation in 4300-4399, prng, tokens, waitFor, corpus loader.
gates/        One file per gate (a.ts ... m.ts), gates/index.ts runs all and prints a results table.
test/         vitest unit tests, one or more per module.
scripts/      fetch-corpus.mjs.
corpus/       manifest, handwritten, specs list (fetched/ gitignored).
results/      gates.md, gates.json written by the gate runner.
```

Each `src/<module>/` has a `README.md`: purpose, public functions, what it may import. Dependency direction: `markdown` <- `crdt` <- `engine` <- {`relay`, `daemon`}; `git` is standalone and used by `relay` (and `daemon` for its git awareness, which it already has in spike 3). `testkit` may import anything; `src/` never imports `testkit`.

Rule for "no other module touches Yjs types": `relay` receives a Hocuspocus `Document` (which is a `Y.Doc`) and passes it into `crdt`/`engine` functions typed as the opaque `CrdtDoc` alias; it never calls Yjs APIs itself. A grep test in `test/` enforces that only `src/crdt/**` imports `yjs`, `y-protocols` or `@tiptap/y-tiptap`, and that `src/relay` imports Hocuspocus only.

## 3. The CRDT interface (spike 5's five points, concretely)

`src/crdt/index.ts` exports these and nothing Yjs-typed except the opaque `CrdtDoc` (= `Y.Doc`), `CrdtSnapshot` (opaque bytes, `Uint8Array`) and `CrdtUpdate` (`Uint8Array`):

1. **Seed and read.** `createDoc()` (gc: false), `seed(doc, pmDoc, {clientId})`, `read(doc): PMNode` (decoded leaf marks, root attrs), `encodeState(doc)`, `applyUpdate(doc, update, origin?)`, `stateVector`, `onUpdate`.
2. **Editor plugins.** `editorPlugins(doc, {cursors?, undo?})` returns `[ySyncPlugin, leafMarksPlugin, rootAttrsPlugin, ...]` in the required order. A schema test asserts every inline atom type declares `leafMarks`.
3. **Relay per-update hook.** `inspectUpdate(update): {clientId, from, to}[]` (from `Y.parseUpdateMeta`), `recordAttribution(doc, ranges, user, at)`, `authorOf(doc, clientId)`.
4. **Fork, diff, apply.** `snapshot(doc): CrdtSnapshot`, `forkDiffMerge(doc, base: CrdtSnapshot, target: PMNode, {clientId, origin, author}) -> {update, counters, forked}`: fork at `base` (or apply directly when `base` equals the live state), apply spike 3's two-way diff from the fork's content to `target`, verify the fork equals `target` (repair with `updateYFragment` on mismatch, counted), merge the fork's update into `doc`. `blockStatesAt(doc, snapshot?) -> Map<blockId, signature>` for review flags, where blockId is the textblock element's Yjs item id and the signature covers attributes and formatted content including inline atoms; `resurrectBlock(...)` for deleted-upstream-edited-locally.
5. **Anchors.** `anchorAt(doc, textOffset, assoc)` and `resolveAnchor(doc, anchor) -> textOffset | null`, over a defined plain-text projection of the document (textblocks joined by `\n`; inline atoms contribute a fixed placeholder character). The quote-selector logic (fuzzy match, acceptance rule of S2-9) is plain string code and lives in `engine/`.

Plus a small typed accessor for JSON values in named maps (`getMeta(doc, map, key)`, `setMeta`, `transact(doc, fn, origin)`), so engine can keep its records without touching `Y.Map`.

## 4. The document, as stored in one `Y.Doc`

| Name | Type | Contents | Written by |
|---|---|---|---|
| `prosemirror` | XmlFragment | the document | editors, daemon, engine |
| `phraise-doc` | Map | root attrs `lead`, `eol` | codec, rootAttrs plugin |
| `phraise` | Map | `docId`, `branch`, `path`, `generation`; `base` = `{id, commit}`; `snapshot:<baseId>` (base64); `rebase:<id>` records keyed by `hash(baseId, target)` (fixes S2-11); `ack:<rebaseId>:<clientId>`; `lastCommit`; `editorsSinceCommit:<user>` = true | engine |
| `phraise-authors` | Map | clientId -> `{name, email?, kind: human, git, import, seed, generation}` | relay hook, engine |
| `phraise-attribution` | Map | spike 5's ranges per clientId with user and time | relay hook |
| `phraise-attribution-conflicts` | Map | kept for diagnostics; forged updates are now rejected before apply | relay |
| `review` | Map | blockId -> `{rebaseId, reason}`; `cleared:<blockId>` for review clearing | every replica |
| `comments` | Map | commentId -> record: anchor pair, quote selectors, author, created, body, `replies[]`, `resolved` | editors, engine |

Integration generalization (spike 2 used `paragraph`, `heading`, `code_block` with one `XmlText` child): in the full schema a textblock is any element whose node type `isTextblock` (paragraph, heading, code_block, table_cell and table_header content paragraphs) and whose children may be several `XmlText` runs and inline-atom `XmlElement`s. The signature of a block at a snapshot is computed from the element's children at that snapshot (`toDelta(snapshot)` per text run, attributes of atoms), not from the first `XmlText` only.

## 5. Git layout (section D2 as amended, validated here)

- The **remote** is a local bare repository (`git init --bare`) created by the testkit under `$TMPDIR`. Humans and "someone else" push to it from ordinary clones.
- The relay keeps a **cache repository** (bare) in its data directory, fetches from the remote, creates objects there with plumbing (`hash-object -w`, a temporary index via `GIT_INDEX_FILE`, `write-tree`, `commit-tree`), and pushes. It never uses a working tree.
- **Head polling:** `git ls-remote <remote> refs/heads/<branch>` at a configurable interval (default 1 s, tests 100 to 250 ms), then `git fetch` when it moved.
- **Draft ref:** `refs/phraise/drafts/<branch>`, one per branch, written with `git push --force-with-lease=refs/phraise/drafts/<branch>:<expected-or-empty> <cache> <commit>:refs/phraise/drafts/<branch>` (never a `+` refspec, spike 4 pitfall). Expected is the draft commit this relay last wrote or read.
- **Draft commit shape:** first parent = the branch commit the drafts are based on; tree = that commit's tree with each live document's rendered Markdown at its real path. Phraise's sidecar data is **not** in the draft tree; it is the tree of a parentless **second parent** commit containing `.phraise/<path>.ydoc` (the full CRDT state, comments and attribution included) and `.phraise/<path>.json` (docId, generation, base commit, flushedAt). This keeps `git diff <branch> refs/phraise/drafts/<branch>` exactly the uncommitted Markdown changes, while every durable byte stays reachable from the ref. This deviates from the amendment's "Phraise's data under `.phraise/` in the tree"; recorded as a decision.
- **Restore:** a relay opening a document with no local state reads the draft ref; if it has `.phraise/<path>.ydoc`, the document is that state (then rebased if the branch head moved past its base). Otherwise seed from the branch head.
- **Commit:** serialize, write blob, tree on the head's tree, commit with parent = expected head, author = the committing user, message plus `Co-authored-by:` trailers for every other user in `editorsSinceCommit`; push `<commit>:refs/heads/<branch>` with `--force-with-lease=refs/heads/<branch>:<expected head>`. On rejection: fetch, rebase the document, retry (bounded). After success: set `base` to the new commit with the snapshot taken at serialization time (no re-seed), clear `editorsSinceCommit`, rewrite or delete the draft.
- Author identity: stub. A user is `{name, email}` from the auth token `name` (email `<name>@users.phraise.test`).

## 6. Relay

`startRelay({port, dataDir, remote, branches?, timings, auth?}) -> RelayHandle` runs Hocuspocus 4.7 in-process with the SQLite extension, `yDocOptions: {gc: false}`; `src/relay/cli.ts` wraps it for child-process runs (needed for memory measurement and hard kills). Binds 127.0.0.1.

- **Document names:** `<branch>:g<generation>:<path>`. `GET /resolve?branch=&path=` returns the current name and generation, opening the document if needed.
- **Auth stub:** the connection token is the user name. `onAuthenticate` stores it in the context.
- **Forged identity rejection (gate B):** for every incoming Yjs update message on a connection, the relay decodes client ids with `inspectUpdate` before Hocuspocus applies it. A client id already mapped to another user, or a deterministic seed, git or generation peer, is a forgery: the message is dropped (not applied, not broadcast) and the connection is closed. New client ids are mapped to the connection's user. The initial sync-step-2 message may legitimately carry other users' structs the relay lacks (after a relay state loss); those are accepted only for ids the relay already maps to another user, never re-attributed, and this residual is documented. Find the Hocuspocus 4.7 hook that runs before apply (`beforeHandleMessage` or `beforeSync`) by reading its source in `node_modules`.
- **Open:** `onLoadDocument`: SQLite state if present; else draft restore (section 5); else seed from the branch head deterministically (seed peer = `hash(docId, commit, generation)`).
- **Integration hook** on the relay's own document, and the relay acks its own rebase records immediately (spike 5 S5-5).
- **Draft flusher:** per branch, trailing debounce plus a maximum interval (defaults 2 s and 60 s; tests shorter), and on demand via `POST /flush`.
- **Head poller:** per branch with open documents. On a new head, rebase every open document of the branch whose file changed, serialized per document (a per-document promise queue).
- **Commit:** `POST /commit {branch, path, user, message?}`.
- **Compaction and generations:** section 7. `POST /compact {branch, path}` forces it; automatic at a quiet point when enabled.
- **Other HTTP:** `GET /state/<docName>` raw state, `GET /markdown/<docName>`, `POST /poll` (poll heads now), `GET /health`. All JSON.

## 7. Generations (D1 as amended; gate K)

- **Compaction** happens only when a document has no connections and its encoded state is above a threshold (or on `POST /compact`). Generation `g+1` is built in two deterministic steps so that a base snapshot exists in it:
  1. seed a fresh doc from the **base commit's** Markdown with peer `hash(docId, baseCommit, g+1)`; its snapshot is the new `snapshot:<baseId>`, so the next rebase forks exactly as before;
  2. `forkDiffMerge` from that seed to the old generation's **current content** (read as a ProseMirror doc, not re-parsed from a rendering) with a generation-carry peer `hash(docId, g+1, "carry")` registered as author kind `generation`. Its snapshot is stored as `generationBase`, the state that equals the old generation's final content.
  Carried over as data: `base` pointer, `editorsSinceCommit`, comments (re-anchored by quote selectors against the new generation, method recorded), open review flags (re-keyed by block index and content), the author list. Per-range attribution of uncommitted text is summarized to the carry peer; that loss is stated in the findings.
- **Retention:** the relay keeps generation `g`'s final encoded state (which includes its snapshot of the final content) in its data directory for a grace period (default 7 days; tests use seconds). `phraise.generation`, `phraise.movedTo` mark the move.
- **Returning replica within grace:** it connects to the old document name. The relay serves the retained generation as a read-write document. When that document changes after compaction, the relay imports the difference into the current generation by fork, diff, merge: fork the current generation at `generationBase`, diff from the old generation's final content to its current content (both read as ProseMirror docs), merge with a fresh client id attributed to the connection's user. Then it tells the client (stateless message plus `movedTo`) to switch; the client reloads from the new name. Nothing is lost. A second returning replica for the same old generation repeats this; the import is computed from the old document's state at the previous import (keep a per-old-generation "last imported" snapshot), not from the final state again, so nothing is imported twice.
- **Past grace:** the retained state is deleted. A connection to the old name is refused with reason `generation-expired`. The editor client keeps its content and exports a conflict copy (Markdown string returned to the caller). The daemon writes `<name>.phraise-conflict-<time>.md` and detaches, as in spike 3.

## 8. Daemon

Spike 3's daemon, with `DocSync` replaced by engine's import and crdt's fork, diff, merge, and:
- it resolves its document name through the relay's `/resolve` and persists it; after a generation change it follows `movedTo`;
- it runs the integration hook like every replica;
- **local save interface (gate J):** HTTP on 127.0.0.1, `GET /versions?path=` lists the versions it wrote (hash, time), each write event carries its version hash, and `POST /save {path, text, base}` imports `text` with the stated base version, then writes the file. A save through the file system without a reported base keeps spike 3's inference.

## 9. Gates and the runner

`npm run gates` runs every gate at full size and prints a table (gate, result, key numbers) and writes `results/gates.md` and `results/gates.json`; exit code non-zero if any gate fails. `npm run gates:quick` runs every gate at small sizes. `npm test` runs the vitest unit tests (fast, under about two minutes). `npm run fetch` fetches the corpus; the gate scripts fetch it if missing.

Each gate lives in `gates/<letter>.ts` exporting `run({quick}) -> GateResult {gate, pass, summary, numbers}` and is runnable alone: `npx tsx gates/<letter>.ts [--quick]`. Gates F and later that fuzz print replayable seeds.

Ports: `testkit/ports.ts` hands out free ports from 4300 to 4399. Every server a test or gate starts is stopped in `finally`, and the runner checks at the end that nothing listens in the range.
